# ADR-001: Выбор технологического стека

**Дата:** 2026-06-04  
**Статус:** Принято

---

## Контекст

Продукт должен работать на Android, iOS, Windows (в перспективе — Android TV, роутеры).  
Требуется встроенный браузерный движок с полным контролем над сетевым стеком и кастомный транспортный протокол поверх TLS.

---

## Решение

### UI / Приложение: Flutter (Dart)
**Причины:**
- Единая кодовая база для Android, iOS, Windows, Android TV
- Уже используется в SafeVPN — команда знает стек
- Нативные плагины для интеграции GeckoView и транспортного модуля

### Браузерный движок
- **Android:** GeckoView — независим от системного WebView, `GeckoRuntimeSettings.setProxy()` для прямой настройки прокси
- **iOS:** WKWebView + WKURLSchemeHandler + локальный HTTP/SOCKS5 сервер внутри процесса
- **Windows:** WebView2 (Chromium-based, нативный для Windows 10/11)

### Транспортный протокол: кастомный поверх TLS
**Причины:**
- Полный контроль над структурой пакетов
- Максимальная гибкость обфускации
- Для DPI выглядит как обычный HTTPS

**Реализация:** Rust (через Flutter FFI)
- Кроссплатформенный
- Высокая производительность
- Единая реализация для всех платформ через FFI

### Сервер-шлюз: Go или Rust
- Декапсуляция кастомного протокола
- Простой HTTP(S)-запрос к целевому сервису

---

## Отклонённые варианты

| Вариант | Причина отказа |
|---------|---------------|
| Kotlin Multiplatform | Нет единого UI, сложнее Windows |
| React Native | Слабая поддержка нативного GeckoView |
| Tauri (только Desktop) | Не покрывает мобильные платформы |
| WebSocket over HTTPS | Менее устойчив к глубокой инспекции |
| WebRTC Data Channel | Сложнее контролировать протокол, зависимость от STUN/TURN |

---

## Последствия

- Требуется Rust-разработчик или изучение Rust для транспортного модуля
- GeckoView увеличивает размер APK (~40–60 MB)
- iOS — наиболее ограниченная платформа, MVP будет функционально урезан
- Android TV использует тот же Flutter + GeckoView код с адаптацией под D-pad UI
